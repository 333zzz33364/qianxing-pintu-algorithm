## 通用到什么程度

支持本项目已经查证的静态图片控件组：矩形、椭圆、等腰三角形，以及有可信模板的原生图片和根遮罩。画布尺寸由配方决定；配方提取支持当前静态图片结构，子控件锚点须居中，不支持X/Y轴倾斜。GUID号段检查沿用已验证样本的保守约束，不作为所有GIA控件类型的官方格式定论。

通用算法根据明确配方生成；它不会自动理解任意PNG的物体语义，也不自动决定审美。处理新图标时，先按参考拆解底板、主体、前景、负形和遮挡，再选择图元、参数和层序。原生资源只复用已查证模板，未知图片不推断纹理方向或透明端点，不用模拟图冒充原生显示。

## 配方与模板

[合集配置.json](合集配置.json)指定交付基线、图标顺序、每组配方/模板路径及新增控件身份区间。配置中的路径相对本目录，不能越出配置目录。七份JSON位于[配方目录](配方/)，对应单组GIA位于[模板目录](模板/)；模板是保留原生资源参数、遮罩和未知字段所需的维护输入，不是废弃交付物。模板及配方引用的SHA256均从实际文件字节核对。

| 数据 | 含义及编辑方式 |
| --- | --- |
| `id`、`name`、`part`、`role` | ID唯一且稳定；显示名允许重复；部件与作用用于语义维护及批量调整 |
| `x/y/width/height/rotation/color` | 位置、尺寸、旋转、RGBA纯色；手电筒部分图元有原有半透明值，不能统一改成255 |
| `pivot/scale/platforms` | 中心、缩放及四平台布局；平台差异保持，不直接压成一套数值 |
| `guid/index` | 当前控件身份及注册索引，分别维护；移动、改色和重排时保留 |
| `source_guid/image_profile` | 选择当前模板的控件和图片样式；原生资源切换须同时匹配资源号与已核对参数 |
| `root_guid/root_index/root_platforms` | 组根身份、索引与平台变换；根遮罩及其余未知字段来自模板 |
| `adjustments.parts/elements` | 对部件或独立ID应用dx、dy、scale、rotation、color、enabled |

`elements`按后景至前景排序；GIA的children方向相反，由生成器统一维护。删除元素或设置enabled=false会移除其实体和引用；重排不重新分配现有身份。新增图元可由几何工具产生，或复制配方中的元素后更换ID并删除`guid/index`；`source_guid`可以继续选择样式模板。新增身份从配置区间按当前元素序号分配，跨组冲突仍会被严格拒绝。每组默认上限49，扩展预算必须显式声明，不能用增加交付版本绕过预算。

图片样式把资源/颜色与其余原生参数分开。无变化时逐控件复用完整原字节；改动仅更新目标控件的已知字段，同时维护名称双写、owner、父子、locator、注册索引和平台变换。新增控件克隆必要模板，附属图片参数与遮罩回读核对。合包只接受公共外层元数据一致的来源，发现不一致就拒绝，不默默合并未知字段。

## 可复用的生成方法

1. 先组织语义部件和遮挡层序。图元预算优先保轮廓、比例、位置、负形和连通，再增加细节和色阶；不要让大面积主体分数掩盖眼睛、端头等小区域退步。
2. 圆角矩形由同色两矩形和四圆拼成，极限半径跳过退化矩形与重复圆；旋转前先计算每个局部中心，再整体旋转。胶囊等高宽时直接用圆。
3. 先对完整凸多边形裁切，再分解成可用的等腰三角形；选择图元数较少的三角剖分并校验面积、连通及透明洞，避免先分解再逐片缩小造成接缝。旧`Drawing.polygon/clip_convex`仍拒绝凹轮廓；新的`图元优化.contour_ops`单独支持简单凹单环，不支持孔洞、自交或退化轮廓。
4. 圆角范围应约束底板和全部前景。原生图片像素未知时，整个矩形只能作为保守上界；椭圆边界函数为360点采样，不能把采样检查说成解析证明。
5. 纯色背景上的硬角可用同色负形扣角。`rounding_patch`仅适用于已知两条边与圆角半径，支持的较小夹角严格大于约53.1301度且小于180度；三等腰三角是圆弧近似。调用者还须检查可用边长、图层位置和扣角范围，不能直接用于未知纹理、渐变或透明背景。
6. 原生渐变接缝先依据实际截图定位；同色端部衬底或窄盖边须位于正确层序，并保留原生图片参数。资源真实性、截图辅助模型和基础几何预览分别记录。

## 描线轮廓、接缝与冗余清理

先读当前授权预算，再组织主轮廓、凹口、尖梢、负形、连通关系和层序；用户描线是几何约束，不能直接把红绿笔画当作素材颜色。截图描线可先配准到原图坐标，记录变换和误差边界，再人工确定有意义的轮廓点。不要逐点追随低清锯齿；椭圆适合概括平滑主体，明显分束凹口和尖梢应保留闭合轮廓。新增接口不会自动识别PNG语义、追踪图片或替代人工设计。

`contour_ops(points)`接收3至128点的单环点序列，可含与首点重复的末点。它先检查有限坐标、重复点、折返、非相邻边交叉/接触及退化；仅移除同向共线的中间点。统一起点、绕向和坐标尺度后，枚举有效对角线，用区间动态规划选择总成本最少的剖分。成本为各三角片经过本模块等腰分解后产生的图元数；等腰、直角特例保留，锐角且外心在内部时可改为三片，其余回退六版分解。返回`(x, y, width, height, rotation)`列表，可直接交给`Drawing.add`。它不支持孔洞、多环、自触、曲线或凹轮廓裁切；超过128点应先人工简化。

“最少”仅指**给定输入顶点、有效三角剖分和当前等腰分片规则下的最少成本**，不表示所有基础图形组合中的全局最少，也不计描边、负形、色阶和身份开销。未扩片结果核对面积；凹口和覆盖还要单独检查，不能只看总面积。轮廓点数受限是为了控制动态规划成本，不是GIA格式限制。

动态规划仅保留区间成本、获选断点和有效对角线，获选三角在输出时重算，不缓存全部候选分片；状态内存为O(n²)。当前候选三角的内部点检查仍需扫描轮廓，最坏时间为O(n⁴)，128点是输入硬上限，不是响应速度承诺；日常优先使用不超过32个有意义的轮廓点，复杂轮廓先简化或拆部件。

`triangle_ops(a, b, c)`可独立分解一个非退化三角形；`expand_ops(operations, factor=1.001)`是显式调用的等比例微重叠，宽高乘同一比例、中心与旋转保持。不要分别给宽高加固定值：细长斜片可能因此偏移并漏出接缝。扩片后原顶点仍应处于新三角内，面积会增加，不能再宣称扩片后面积严格等于轮廓。只在允许微量扩边的同色不透明接缝上使用，并检查外轮廓、尖梢和负形；透明、半透明或异色重叠可能变暗/露边，不应直接套用。1.001是可调的本地经验值，不能保证原生采样或实机无缝。

```python
# 使用本目录已有的模块加载方式读取 图元优化.py，得到opt。
ops = opt.contour_ops(points)
# 仅在允许同色不透明微重叠时，显式使用 opt.expand_ops(ops)。
for i, (x, y, w, h, angle) in enumerate(ops, 1):
    drawing.add('主体', f'闭合轮廓片{i}', 'triangle', x, y, w, h,
                '#11192f', angle)
```

清理分两个时点：开始重建前清理一次，轮廓/层序冻结后再分析一次。`cleanup_candidates(scene, render=core.render, margin=2)`只读取**实际GIA回读的基础几何场景**，不改输入或写文件。它按与六版预览一致的4倍采样变换绘制支持区域，从前景向后检查alpha255的保守遮挡，膨胀待删区域并收缩覆盖区域；随后从后景向前检查下方已确定为相同不透明颜色的冗余片，保留必要底层，避免互相作为删除理由。半透明层不能作为不透明遮挡或同色底层依据；完全被后方遍历中已知前景不透明层遮住的半透明图元仍可成为候选。

候选必须再用指定只读PNG渲染函数比较整张清理前后图像；像素不同则整批回撤候选，返回全部`keep_indices`，差异建议保存在`rejected_candidates`。一致时`candidates`记录原始回读索引和原因，`keep_indices`映射同序图元。该函数只提出当前场景建议；应用到配方后仍须另存新交付版本、重新编译并核对身份、层序、四平台及回读预览。不同平台应逐一分析并核对共同可删集合；当前场景采样不能证明其他平台或几何改动后仍可删。先前被遮住的图元在轮廓收窄后可能重新有效，应重新分析并按需恢复。

清理输入要求根变换恰有13项、子记录恰有18项且锚点居中；拒绝根/子X/Y倾斜、长度异常、悬空子引用、原生图片资源和原生遮罩。回读行格式与现有解析器一致，不推定为所有GIA的官方规范。画布外、跨画布或过于靠近边界的图元不作为待删候选，避免把本地预览裁切当作实际遮挡。未知纹理、抗锯齿或实际编辑器采样不由本地几何模拟证明。默认`margin=2`为高分辨率采样像素，允许1至64且不得超过采样画布最长边；默认`max_pixels=16000000`约束4倍采样画布面积。候选数量不保证最大化。渲染器须与当前scene约定一致且不写入资产；本模块将副本交给回调，但无法替用户验证回调的外部行为。

清理还会完整渲染前后两幅图，耗时随采样面积和图元数增加；`max_pixels`仅约束分配规模，不保证运行速度。应在几何阶段完成时集中检查，不在每次拖动或改色时反复执行。缩小预览可用于快速观察，但不能替代最终目标尺寸的清理证明。

归纳出的维护顺序为：**核预算与参考 → 清理并留证 → 建主轮廓与负形 → 补细节 → 冻结后再清理 → 新版GIA回读与局部对照**。预算包含背景、轮廓、细节和新增补片；400或500属于具体任务授权，不更改通用默认49。清理前后证明必须对应最终几何/源码版本，修过接缝后应刷新证据。范围外按稳定ID或明确语义映射比较全部几何、RGBA、资源和相对层序；重新分配身份时不能把几何保持称为控件原字节保持。具体温迪取点、颜色、花篮及500预算留在本地项目的温迪记录，未迁入公共代码。

## 生成与检查

在本仓库任意目录下用 Python 3 运行（除下面的解析库外不安装新依赖）；解析库位置用 `UI_TOOLBOX_ROOT` 指向本机另行准备的 `Miliastra-toolbox-primitive-shape`：

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:UI_TOOLBOX_ROOT='C:\path\to\Miliastra-toolbox-primitive-shape'
python -B '.\算法\10.15-六版算法\统一生成.py' --version 10   # 首次生成；--check 需要已保存过同版 GIA
python -B '.\算法\10.15-六版算法\统一生成.py' --check        # 只读核对
python -B '.\算法\10.15-六版算法\回归检查.py'                # 完整回归（需自备基线 GIA 与解析库环境）
```

默认生成只写GIA；`--check`只核对已保存GIA，不创建目录或报告。已有同版GIA不同则在创建任何输出前拒绝。配置基线为第10版，配方内容变动须显式选择后续版本，例如：

```powershell
python -B '.\算法\10.15-六版算法\统一生成.py' --version 11
```

此命令是后续维护示例，本次没有生成第11版。`--manifest`可选择其他配置，`--output-root`可指定交付父目录；每个版本使用独立目录。`--extract 单组.gia --recipe 新配方.json`可提取配方，目标已存在时拒绝覆盖；将可信单组复制到模板目录并在配置中登记哈希与独立身份区间后使用。多组合集先通过`合包工具.split_bundle`拆分，不能冒充单组提取。

外部运行依赖是另行克隆的 `Miliastra-toolbox-primitive-shape` 解析库及其 Python 环境，本仓库不包含它；用环境变量 `UI_TOOLBOX_ROOT` 显式指向该工具根目录。基础图形预览还使用该环境里的 NumPy/OpenCV，带未知图片或原生遮罩时拒绝生成假预览。
