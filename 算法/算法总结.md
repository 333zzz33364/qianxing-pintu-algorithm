# UI 图元算法总结与优化（2026-10-24）

本文把现行「六版算法」的结构、一次素材从参考图到 GIA 的实际流程、本次太阳花交付沉淀出的配方规则、
以及本轮做的优化与自动化的边界写在一起，供以后做新素材时直接照做。
坐标、颜色、图元数属于具体交付，写在各自交付目录的 `配方.json` 里，本文只写方法与约定。

---

## 1. 现行算法的分层

算法不是"一个程序"，而是四层职责分开的结构：

| 层 | 位置 | 只管什么 | 不做什么 |
| --- | --- | --- | --- |
| 几何层 | `算法/10.15-六版算法/几何工具.py` | 圆角矩形、胶囊、椭圆、凸多边形最小三角分解、边界检查 | 不知道颜色语义、不知道 GIA |
| 优化层 | `算法/10.15-六版算法/图元优化.py` | 简单凹单环剖分、锐角三片、等比例微重叠、冗余候选与像素回撤 | 不自动识别图片、不替代设计判断 |
| 编译层 | `算法/10.15-六版算法/生成图元.py` | 配方校验、四平台变换、原生样式、身份分配、`build/verify/render`、两种模式互转 | 不含任何美术坐标 |
| 容器层 | `算法/10.15-六版算法/合包工具.py` | GIA 检查、严格拆组、全局身份查重、原字节合包 | 不改几何 |

上层再包三样东西：`统一生成.py`（七图合集的配置驱动生成）、`回归检查.py`（34 项本地回归）、
以及每个交付目录自己的 `生成.py`（只负责"把这张图画成图元"）。

关键约束（每次都要过）：

1. 每组默认上限 **49** 图元；不够用时先报不足、申请扩展，扩到多少写在配方 `max_elements` 与
   `element_budget_mode='extended'`，不能靠加版本号绕过。
2. 身份必须落在模板允许的号段（`guid >> 27` 与模板一致），并避开其它交付已用区间；注册索引同理。
3. 图元边界必须落在画布内；`elements` 顺序是后景→前景，GIA 的 children 方向相反，由生成器处理。
4. 配方是 `--init` 时的快照：**改了生成器里的几何，必须先删 `配方.json` 再 `--init`**。

## 2. 一次素材的实际流程

以太阳花.1（`交付物/太阳花.1-经典+超限/`）为例，实际顺序是：

1. **量参考**：从原图取花瓣数（角度互相关定周期）、半径、花心直径、主色；
   坐标先按源图像素量，再乘画布缩放系数（512 / 源图主体直径）换算。
2. **拆语义**：花瓣环 → 花喉暖带 → 花心外圈 → 花心底面 → 花心颗粒。先轮廓、后细节。
3. **写几何**：交付目录 `生成.py` 里的绘制函数逐件产出图元（可调用 `算法/造型.py`）。
4. **初始化配方**：`--init` 落盘 `配方.json`。
5. **草稿迭代**：`--draft` 输出到 `过程预览/`，看 `参考对照.png` 逐件校正。
6. **冻结**：`--finalize`，同版内容不同就拒绝覆盖。
7. **验证**：`--check` + 公共回归 34/34 + 独立复核；`验证记录.json` 存全部哈希与统计。

预算检查在制作过程中要反复看：`造型.预算(elements, limit)` 直接返回总数、是否超、各部件占用。

## 3. 本次沉淀的配方规则

这些是同一造型下次可以直接复用的结论：

| 部件 | 做法 | 理由 |
| --- | --- | --- |
| 花瓣环 | 每瓣一个椭圆，`width` 横向、`height` 径向，`rotation` 取方位角；瓣数由参考图周期定（太阳花 20 瓣≈18°、立体版 16 瓣≈22.5°） | 椭圆端头圆润，少量图元就能得到圆瓣；比三角形拼花瓣省一个数量级 |
| 花瓣分色 | 无描边时用两色交替（如 `#FFD522`/`#FFC60C`）代替花瓣间的细描线 | 描线要每个接缝一个图元，成本高；交替明度差在图标尺寸下已经能读出花瓣 |
| 立体感 | 每瓣两层：暗边椭圆＋外移亮面椭圆（亮面中心半径 +10 左右，宽高比约 0.65/0.76） | 亮面外移使暗边只在瓣根一侧变厚，读作"尖端受光"，避免均匀描边的卡通感 |
| 花喉 | 花瓣根部一层暖色椭圆（比花心大 10–30px） | 参考图里花心周围有暖色过渡，一层椭圆即可暗示 |
| 花心颗粒 | 抖动三角点阵：间距 22–24、直径 19–20，位置抖动 ±0.34 间距、直径 ±0.84–1.08，固定种子 | 同心圆环会露出"靶心"；抖动点阵在同等数量下更像密集颗粒，且可复现 |
| 顺序 | 花瓣 → 花喉 → 花心外圈 → 底面 → 颗粒 | 颗粒最后画，才不会被底面盖住 |
| 颗粒范围 | 半径取"花心底面半径 − 颗粒半径"，别让颗粒压到外圈 | 压到外圈会像出界的圆点 |

预算怎么分（太阳花实测）：

- 20 瓣×2 色 + 暖带 1 + 花心 2 + 颗粒 42 = 65（平面版）；
- 16 瓣×2 层 + 花心 2 + 颗粒 34 = 68（立体版）；
- 想靠"少画几瓣、多画几颗颗粒"互换时，优先保花瓣数和花心直径，这两项最影响识别。

## 4. 本轮做的优化

### 4.1 参数化造型库：`算法/造型.py`

以前每做一朵花，都要在交付脚本里手写 20 个椭圆的坐标。现在收敛成四个函数：

```python
花瓣环(d, '花瓣', 20, 中心=(256, 256), 半径=158, 宽=76, 高=190,
       颜色='#FFD522', 交替色='#FFC60C')
立体花瓣环(d, '花瓣', 16, 中心=(256, 256), 半径=155, 宽=96, 高=192,
           暗边色='#DE9A08', 亮面色='#FFDD48')
花心(d, '花心', 中心=(256, 256), 直径=196, 外圈='#5C2A11', 底面='#6B3417')
颗粒(d, '花心颗粒', 中心=(256, 256), 半径=79, 间距=24.5, 直径=20,
     颜色='#95502A', 种子=20261025)
```

自带 `预算()` 与 `__main__` 自检（`python 造型.py` 直接跑，不写文件）。
它只产几何，不碰身份与编译，所以既能被交付脚本用，也能被自动工具用。
已经冻结的交付不回改，新素材直接用。

### 4.2 形状参数按"回读画法"标定

这轮踩到的第一个坑：`cv2.fitEllipse` 的 size 是全轴长，`cv2.ellipse` 的 axes 是半轴，
而本算法元素的 `width/height` 又是全轴长；再加上 `element_rows` 里 `rotation` 取负、
`render` 里 y 轴翻转，很容易出现"预览和配方对不上"。

结论（写进自动工具里当约定）：

- 元素 `(width, height, rotation)` ↔ `cv2.ellipse(center, (width/2, height/2), rotation)`；
- 矩形与三角要用 `render` 那套顶点旋转（`angle=-rotation`、`y' = cy - dx·sin + dy·cos`），
  不能用 `cv2.boxPoints` 的角度约定直接套；
- 判断某个候选像不像，**要用同一套画法栅格化再算 IoU**，否则优化方向和最终像素不是一回事。

### 4.3 自动转 GIA 工具（未随本仓库发布）

把"图 → 配方 → GIA"这条链做成可执行的工具；工具本身未随本仓库发布。
管线：去背景 → 适配画布 → kmeans 调色板 → 按面积分层 → 连通域拟合
（椭圆／旋转矩形／圆角矩形／简单多边形三角化，按 IoU 择优）→ 预算配额取舍 → 编译 → 报告。

其中三条是从失败里改出来的规则，值得记住：

1. **预算要按面积配额分配，不能按处理顺序花光**：否则大色块吃掉全部预算，花心这类
   面积小但关键的层一个图元都拿不到（实测第一版就没有花心）。
2. **多裂片轮廓不要硬拆三角片**：20 瓣的花瓣环若三角化，会变成一圈细长"放射线"，
   既不像原图又吃预算；三角化只留给顶点 ≤12 的真多边形，圆形/裂片交给填充或拆分。
3. **去底后要清掉贴边的浅色残留层**：JPEG 白底的浅灰边缘会自成一层，被拟合后在
   画布四周生成莫名其妙的色块；但只丢"贴边"的，图标内部的白色主体必须保留。

## 5. 自动化的边界（实测）

| 图类型 | 结果 | 说明 |
| --- | --- | --- |
| 纯色平涂图标（相册等） | 可用 | 覆盖率 0.65、MAE 14 左右，形状基本对 |
| 平涂 + 多色块（太阳花） | 可用作初稿 | 花瓣环会被并成一个圆盘、花心为实心圆；花瓣与颗粒细节要手调 |
| 圆角方形底板 + 简单主体 | 底板准确 | 圆角矩形候选直接命中；主体若是复杂曲线（电话手柄）只能给出外接矩形 |
| 渐变 / 半透明 / 照片 | 不适用 | 渐变会被量化成色带，输出没有意义；需要先降色数大幅简化，或直接手工做 |

一句话：**工具负责出结构正确的初稿（合法 GIA、可编辑配方、可量化误差），细节仍要靠配方手调。**
这跟算法本身的定位一致——算法只按明确配方生成，不替人做审美判断。

## 6. 还能往哪优化

1. **裂片检测**：花瓣环被并成圆盘的根因是"同色花瓣连成一片"。下一步可在轮廓的凹点
   （凸性缺陷）上找瓣间缝，再按缝切分成瓣逐瓣拟合，能显著改善花卉类图。
2. **多形状分解复杂主体**：电话手柄这类曲线体，单形状拟合注定失真；可对局部降采样后
   允许 8–20 个三角片，用剩余预算"补形"。
3. **渐变近似**：同一色相的多条色带可以用"同心多层椭圆"近似，比逐带矩形干净。
4. **造型库继续收编**：胶囊、圆角底板、同心环、阴影层都可以照 `造型.py` 的方式参数化。
