# 千星拼图算法

用几何图元拼出千星奇域（千星沙箱）的静态图片控件：给定参考图和图元预算，把图形拆成可以维护的**配方**，配合可信的**原生模板**保留图片参数与遮罩字段，生成可直接导入编辑器的 GIA 素材组。

Recipe-driven GIA generator for static image controls in *Genshin Impact* Miliastra (UGC) levels: primitives + native templates → import-ready `.gia` bundles, with read-only checks and a 34-case local regression suite.

## 这是什么

- 一个**配方驱动**的生成器：图形的几何、颜色、层序、平台布局和控件身份都写在 JSON 配方里，生成器按配方产出 GIA，不复制粘贴编译器、不保留旧版本源码。
- 一套**保真**的字段维护方式：未改动的控件逐控件复用原字节，改动只更新目标控件的已知字段，同时维护名称双写、owner、父子关系、locator、注册索引和四平台变换。
- 一套**可核对**的交付流程：只读 `--check`、同版覆盖保护、跨组身份唯一性检查、合包元数据一致检查，以及覆盖几何、轮廓剖分、冗余清理和编辑行为的本地回归。

## 能做什么，不能做什么

**能做**：按明确配方生成矩形 / 椭圆 / 等腰三角形组成的静态图片控件；用可信模板承载原生图片资源与根遮罩；在四平台保持各自布局；只读核对、增量编辑（增删图元、改色、重排、调整部件）、单组与多组合包。

**不能做**：不会理解任意 PNG 的物体语义，不会自动决定审美，不会自动挑图元。它按配方工作——拆解、选形、参数和层序由人决定。预览是本地基础几何模拟，**不能替代编辑器里的实际导入、原生采样与容量验收**。

## 环境要求与准备

- **Python 3**（本仓库在 3.13 下验证）。生成、只读检查与合包只用标准库。
- **解析库**：GIA 容器的解析与经典/超限模式转换来自第三方仓库
  [Miliastra-toolbox-primitive-shape](https://github.com/1475505/Miliastra-toolbox-primitive-shape)（MIT，作者 LiuL），**本仓库不包含它**，请另行克隆，并用环境变量指向其根目录：

  ```powershell
  $env:UI_TOOLBOX_ROOT='C:\path\to\Miliastra-toolbox-primitive-shape'
  ```

- **可选依赖**：回读预览与清理候选需要 NumPy / OpenCV，对应 `requirements.txt`。带未知图片或原生遮罩时，算法会拒绝生成假预览而不是静默降级。

## 快速开始

```powershell
$env:UI_TOOLBOX_ROOT='C:\path\to\Miliastra-toolbox-primitive-shape'

# 1) 按当前配方生成第 10 版合集（写到 .\交付物\手机图标合集.10\）
python -B '.\算法\10.15-六版算法\统一生成.py' --version 10

# 2) 只读核对已保存的 GIA 与当前配方重建是否一致
python -B '.\算法\10.15-六版算法\统一生成.py' --check

# 3) 配方改动后递增交付版本（算法版本与交付版本分别管理）
python -B '.\算法\10.15-六版算法\统一生成.py' --version 11

# 4) 从单组 GIA 提取可编辑配方（目标已存在时拒绝覆盖）
python -B '.\算法\10.15-六版算法\统一生成.py' --extract .\某单组.gia --recipe .\新配方.json

# 5) 完整回归（34 项；需要先执行过第 1 步，见下）
python -B '.\算法\10.15-六版算法\回归检查.py'
```

- 生成**只写** GIA，不写别的东西；`--check` 只核对、不创建目录、不输出报告；同版已有资产与当前重建不同时，在创建任何输出之前就拒绝。
- `--manifest` 换配置，`--output-root` 换交付父目录，每个版本使用独立目录。
- 回归读取 `.\交付物\手机图标合集.10\手机图标合集.10.超限.gia` 作为基线，所以**先跑一次生成**再跑回归。回归本身只写系统临时目录，不动交付物。

第一次生成出的合集 SHA256 应当等于 `2dd56424e07f3942c9c97a607f50a7afbfaf4709cfcc59d7f53a36c8034a9d51`——这既是配置里的交付基线，也是本仓库配方与模板自洽的证明。

## 配方与模板

配方（`配方/*.json`）是可编辑的事实来源：`id/name/part/role` 语义，`x/y/width/height/rotation/color` 几何与纯色，`pivot/scale/platforms` 四平台布局，`guid/index` 控件身份，`source_guid/image_profile` 图片样式来源，`root_guid/root_index/root_platforms` 组根身份，`adjustments` 批量或定向调整。字段语义、编辑方式和限制见 [算法说明](算法/10.15-六版算法/算法说明.md)。

模板（`模板/*.gia`）是**必要维护输入**，不是废弃产物：原生图片参数、根遮罩和未知字段都从模板保留。模板与配方里的 SHA256 会在生成前逐字节核对，模板被改动会直接报错。

基本规则：

- `elements` 按后景至前景排序，GIA 的 `children` 方向相反，由生成器维护。
- 删除元素或 `enabled=false` 会移除其实体与引用；重排不重新分配已有身份。
- 新增控件从配置的号段按元素序号分配身份，跨组冲突一律拒绝。
- 每组默认上限 49 个图元，扩展预算必须显式声明，不能用递增交付版本绕过预算。
- 合包只接受公共外层元数据一致的来源，不一致就拒绝，不静默合并未知字段。

## 示例交付：太阳花.1

`交付物/太阳花.1-经典+超限/` 是一份完整但**有意不完整**的示例：

- `配方.json` 保存两组（平面 65 图元 / 立体 68 图元）的几何、颜色、层序、身份与扩展预算声明；
- `生成.py` 是这份交付自己的生成器，读取配方后调用 `算法/10.15-六版算法/` 的 `build/verify/render/bundle`。

仓库**不包含**成品 GIA、预览 PNG 和两张参考图；公开副本的 `preserved_inputs` 也已过滤为仓库内 20 个算法文件的哈希，因为原清单用于校验维护版的其他交付资产。因此：

- 想复现这份示例，需要把两张参考图按配方里的 `reference_image` 文件名放进 `参考素材/`（文件名与 SHA256 见配方），并保证 `UI_TOOLBOX_ROOT` 可用；缺图或哈希不符会直接报错，不会静默生成。
- 发布副本在本机实测过 `--finalize` 与 `--check`：两组共 133 图元、135 个身份、540 条四平台布局，合集 SHA256 与维护版一致。
- 生成器写入的 GIA、预览与验证记录都在 `.gitignore` 里，不会进入仓库。

两条可直接复用的约定：

- 元素 `(width, height, rotation)` ↔ `cv2.ellipse(center, (width/2, height/2), rotation)`；
- 矩形与三角形必须按 `render` 的顶点旋转（`angle=-rotation`、`y' = cy - dx·sin + dy·cos`），不能直接套 `cv2.boxPoints` 的角度约定。
